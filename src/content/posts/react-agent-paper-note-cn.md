参考来源：[ReAct: Synergizing Reasoning and Acting in Language Models](https://arxiv.org/abs/2210.03629)，以及 [Google Research 对 ReAct 的介绍](https://research.google/blog/react-synergizing-reasoning-and-acting-in-language-models/)。

做 Agent 时，最容易把进展误判成“工具越来越多”。搜索、浏览器、代码执行和文件系统都接上以后，系统确实更像一个能办事的东西；但一旦某一步失败，工具清单几乎解释不了问题。真正需要回答的是：模型依据什么决定下一步，工具返回后有没有改变判断，失败能不能定位到某个具体动作。

最值得留下的判断是：Agent 的核心能力不是连续生成更长的文字，而是让外部反馈有机会打断内部推演。论文把这件事写成交替出现的 `Thought`、`Action`、`Observation`。今天的接口未必保留这些字段，但运行日志、工具调用记录、测试输出和浏览器状态仍在承担同一职责。

## ReAct 真正补上的，是观察回路

ReAct 建立在 Chain-of-Thought 的局限之上。只让模型写推理，模型可以分解问题，也可以把中间结论说得很完整；但它仍然只能在 prompt 和参数记忆里自洽。网页当前是什么状态、数据库里是否真的有记录、代码改完测试是否通过，都必须由外部环境回答。

论文在 HotpotQA 和 FEVER 上让模型使用 Wikipedia API，推理轨迹因此不再是一次性独白：先判断需要查什么，再搜索或定位，拿到观察后更新计划。论文的结果表明，把推理与外部观察接在一起，能缓解只在内部推演时的幻觉和错误传播；但这些基准结果应被看作范式的证据，而不是今天产品可靠性的保证。[论文摘要与结果](https://arxiv.org/abs/2210.03629)

这让我更在意观察能否真正改变下一步：动作把模型接到环境，环境又把新的事实送回推理。没有这条回路，模型可能只是把错误前提包装得更长；有了这条回路，至少存在被事实纠正的机会。

## 工具调用必须改变任务状态

把工具当作“模型答不出来时查一下”，会低估它在 Agent 里的位置。一次搜索是否值得发起，取决于当前缺什么信息；搜索返回什么，又决定下一步继续查、换关键词还是结束。动作不是答案生成后的补丁，而是答案形成过程中的状态转移。

这对工具接口提出了比“能不能调用”更具体的要求。搜索结果要能定位来源，代码执行要保留退出状态和工作目录，浏览器操作要让页面变化可观察，空结果和权限错误要与正常结果区分开。否则模型得到的是一个看似有内容、实际无法判断的 `Observation`，后续推理再流畅也没有可靠依据。

从这个角度看，工具设计其实是在设计模型的可见世界。返回太长，关键信息会被噪声淹没；返回太短，模型看不到决定性上下文；没有来源或状态标记，模型无法知道哪些内容可以当作事实。ReAct 没有替工程师决定最佳格式，但它迫使人承认：工具输出会直接进入下一轮判断。

## 轨迹的价值是让错误可归因

最终答案只能告诉人“这次没做对”。完整轨迹则能继续追问：模型是否一开始就误解了目标，是否选错了工具，是否读错了返回，还是看到反例后仍然坚持原计划。`Thought`、`Action`、`Observation` 的价值更像调试接口，而不是可靠性保证。

这也解释了为什么生产系统需要保留足够的过程记录。代码 Agent 的最终补丁之外，还应能回看读过哪些文件、跑过哪些测试、如何处理报错；浏览器 Agent 的最终截图之外，还要知道点击前的页面状态和点击后的返回。轨迹越接近真实因果链，越容易决定该改 prompt、工具、环境还是停止条件。

不过，轨迹并不天然等于真相。模型可以写出漂亮但错误的推理，也可能在观察已经否定原计划时继续向前。因而不应把 `Thought` 当作不可质疑的解释，更稳妥的做法是把它与工具原始返回、最终状态和独立测试放在一起看。

## ReAct 没有替工程约束买单

这套范式提供的是骨架，不是保证。外部数据可能过期，工具可能超时，页面可能变化，权限可能不足。模型能看到观察，不代表观察可靠；能留下轨迹，也不代表知道何时重试、回滚或请求人工确认。

轨迹还有成本。每次推理、调用和返回都会消耗上下文与时间，简单任务不必强行展开长链路。Google Research 的介绍也提到，在动作很多的决策任务里，推理痕迹可以稀疏地出现在关键位置。工程上更合理的目标是保留关键判断和关键状态，而不是把所有中间文字都无限堆积。

假如一次查询返回空结果，下一步还按“记录存在”继续执行，增加再多工具也没有修复这个 Agent。先让这条反证改变动作，再讨论它还能承担多大的任务。
